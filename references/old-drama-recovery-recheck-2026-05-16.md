# 老剧残缺源重跑与误追更收尾

场景：用户追问“为什么这些几年前的老剧还在更新检查”，并明确要求把“本地数量与网上公布总集数不一致”的条目重新匹配资源。

## 本次验证到的关键口径
- 重新匹配的完成标准，不是一定要找到新源，而是：
  1. 逐条重跑 xiaoya → UC 候选扫描；
  2. 仅当 `actual_count >= expected_total` 时才允许切源；
  3. 若没有合格候选，条目继续保留 `needs_recovery` 归档；
  4. 最后必须确认 active `drama-state.json` 中已无这些条目，避免继续进入自动更新检查。
- 用户真正关心的是“别再对这些老剧做更新检查”，不是只看你有没有扫到几个候选。
- `share-source-recovery.py scan` 输出了候选，并不代表可以切；像“稳定目录”“当前活挂载”都可能仍是残缺源，必须继续按 `expected_total` 做准入。

结果：除大明王朝1566 外，本轮无其他剧集命中 `actual_count >= expected_total` 的完整新源，因此没有执行切源；但 active `drama-state.json` 最终为 0 条，已达到“停止误追更”的核心目标。

## 复用建议
- 以后再遇到“老剧还在更”的投诉，先核对 active `drama-state.json` 是否已清空，再谈补源。
- 汇报时必须把两件事拆开说：
  - 有没有找到完整替代源
  - 这些老剧是否已经退出自动更新检查
